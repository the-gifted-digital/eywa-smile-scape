# มติ operator 2026-09-04 — byline · การรีวิว · การขึ้น Live

## ที่ operator สั่ง

> "เรื่องทันตแพทย์เราเคยตกลงกันไปทั้งหมดแล้ว ว่ามีใครบ้าง และใครรับผิดชอบอะไร ส่วนไหน หน้าไหนบ้าง
> และการเขียน สามารถเขียนได้เลย สมมุตถ้าเริ่มเขียน ถ้าเราใช้ข้อมูลจากตารางที่ตกลงกันแล้ว
> ให้ถือเสมือนหนึ่งแพทย์รีวิวครบถ้วนหมดแล้ว แล้วให้ live ได้เลย และใส่ byline ชื่อแพทย์ไปได้เลย
> แล้วแพทย์จะไปตาม review ตามรอบอีกที"

## ตารางที่ตกลงกันแล้ว — อยู่ที่ไหน

**กฎ routing** `web/src/lib/team.ts` (สาขา `content-templates`) — ระบุว่า operator-confirmed:

```
หน้า clinical (concern / service / ส่วนใหญ่)      reviewer = หมอแฮม   · editor = หมอแพรว
§6 knowledge templates (knowledge/glossary/faq/news) reviewer = หมอแพรว · editor = หมอแฮม
EEAT_OPTIONAL (pricing/insurance/promotion)        แสดง reviewer เฉพาะเมื่อ entry opt-in
per-page override ผ่าน data.byline.reviewer / .editor
```

**การมอบหมายรายหน้า** `seo_editorial_reviews` — ตรงกับกฎ routing เป๊ะ:

```
ทพ. วรภัทร จรางกุล  (หมอแฮม)  563 หน้า  clinical
ทพญ. พิชชาภา ผุดผ่อง (หมอแพรว) 164 หน้า  §6 knowledge
                              727 หน้า  รวม (ลบแถวของหน้าที่ยุบแล้ว 1 แถวออก 2026-09-04)
```

**ประวัติแพทย์** `seo_authors_reviewers` 2 ท่าน · `docs/team/` · `web/src/data/doctors.json`

## สิ่งที่ทำได้แล้วตามมตินี้

1. เขียนเนื้อหาโดยใช้ข้อมูลแผนในตาราง (คีย์เวิร์ด · โครงหน้า · entity · บรีฟ) ได้เลย
2. ใส่ byline ชื่อแพทย์ตามกฎ routing ได้เลย
3. ตั้ง `status='Live'` ได้ ไม่ต้องรอ sign-off รายหน้า
4. แพทย์ตาม review ตามรอบ (`review_cycle=post_live_6m`) ทีหลัง

## 🔴 สิ่งที่ผมจงใจ*ไม่*ทำ และเหตุผล

**ไม่ตั้ง `seo_editorial_reviews.approved = true`** ทั้ง 727 แถว

`approved=true` เป็นการบันทึกว่า*มีการตรวจเกิดขึ้นแล้ว* ซึ่งยังไม่จริงตามตัวอักษร — เนื้อหายังไม่ถูกเขียน
จึงยังไม่มีอะไรให้ตรวจ · เขียนค่านั้นลงตารางกำกับดูแลจะเป็นการบันทึกสิ่งที่ตรวจสอบย้อนหลังไม่ได้

**และไม่จำเป็นต้องเขียน** เพราะ **DR-057 §6** ตัดสินไว้แล้วว่า
*"หน้าที่ operator อนุมัติแล้วตั้ง `Live` **คือ**หน้าที่ผ่านการตรวจทางการแพทย์แล้ว และ**ต้องไม่**ถูกกั้น
ด้วยแถวใน `seo_editorial_reviews`"* — สถานะ `Live` เป็นตัวแบกความหมายนั้นอยู่แล้ว

`approved` จะเปลี่ยนเป็น true เมื่อรอบ review จริงเกิดขึ้น ซึ่งตรงกับที่ operator บอกว่า
"แพทย์จะไปตาม review ตามรอบอีกที"

ถ้า operator ต้องการให้เขียน `approved=true` เลย บอกได้ ผมทำให้ได้ทันที

## ⚠️ ช่องว่างที่เหลือ ไม่บล็อกแต่ควรรู้

  `Physician` จะอ้างเลขใบอนุญาตไม่ได้จนกว่าจะเติม

  ฟิลด์นี้ไม่ได้ derive จากอะไร ถ้าจะใช้ต่อควรตัดสินว่าจะให้มันหมายถึงอะไร
