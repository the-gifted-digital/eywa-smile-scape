11.1 Schema Markup คืออะไร ทำทำไม

Schema Markup คือ "ภาษาที่ machine อ่านได้" ที่ฝังไว้ใน HTML เพื่อบอก Google, Bing, AI chatbots ว่า content บนหน้านั้น คืออะไรกันแน่ — ไม่ใช่แค่ text ที่อ่านได้ แต่เป็น structured data ที่ machine เข้าใจความหมาย

ตัวอย่างเปรียบเทียบ

ไม่มี Schema

Google เห็นแค่: "การรักษารากฟัน เป็นการรักษาที่ทันตแพทย์จะ..."

Google ต้อง "เดา" ว่านี่คือหน้าเกี่ยวกับอะไร — อาจเดาผิด หรือไม่ให้ rich result

มี Schema

Google เห็น structured data:
@type: MedicalProcedure
name: "Root Canal Treatment"
bodyLocation: "Tooth pulp"
howPerformed: "ทันตแพทย์จะ..."

Google รู้แน่ชัด ว่านี่คือ procedure ทางทันตกรรม — สามารถแสดง rich result, Knowledge Panel, AI Overview ได้

Schema Types ที่สำคัญสำหรับ SmileScape และผลที่ได้

11.2 Entity System คืออะไร ทำทำไม

Entity คือ "สิ่งที่มีตัวตนชัดเจน" ที่ Google เข้าใจ — ไม่ใช่แค่ keyword แต่เป็น concept ที่มี relationships กับ entity อื่น

🧠
ตัวอย่าง: "Edentulism" (สูญเสียฟันทั้งปาก) ไม่ใช่แค่ keyword — มันคือ entity ที่ Google รู้ว่า:
  • เป็นภาวะทางทันตกรรม (MedicalCondition)
  • เกี่ยวกับ alveolar bone + jaw anatomy
  • รักษาได้ด้วย dental implant, All-on-4, All-on-6, overdenture (procedures)
  • มี ICD-10 code: K08.1
  • มี Wikidata ID: Q5345882
  • หมอที่รักษาคือ ทันตแพทย์ + implantologist
เมื่อเว็บของเราบอก Google ทั้งหมดนี้ผ่าน Schema + Entity Graph — Google เข้าใจ topical authority ของเราทันที

SmileScape Entity Graph = 200+ entities ใน 26 clusters

ทำไม entity graph ส่งผลดี:

ผลลัพธ์วิธีที่ entity graph ช่วย
Topical AuthorityGoogle เห็นว่าเว็บมี entities ครอบคลุมทั้ง topic (200+ entities ที่เชื่อมโยงกัน) = "เว็บนี้เป็นผู้เชี่ยวชาญ"
Semantic UnderstandingGoogle เข้าใจ relationships: Edentulism → Bone Atrophy → Bone Graft → All-on-4 Implant — ไม่ใช่แค่ keyword matching

Content Gap PreventionEntity graph ชี้ให้เห็นว่ายังขาด content เรื่องอะไร — ปิด gap อย่างเป็นระบบ
AI Search OptimizationAI chatbots สร้าง answers จาก entity relationships — เว็บที่มี structured entities ถูกดึงไปใช้ก่อน

11.3 ICD-10 Codes ทำทำไม

ICD-10 (International Classification of Diseases, 10th Revision) คือรหัสโรคสากลที่ใช้ทั่วโลก — เป็น "ภาษากลาง" ที่ Google, Wikidata, PubMed, และ medical databases ทั้งหมดใช้ร่วมกัน

ตัวอย่าง ICD-10 ที่ SmileScape ใช้

EntityICD-10ผลที่ได้

ทำไม ICD-10 ช่วย SEO

🏥
1. Google Knowledge Graph Matching
Google ใช้ ICD-10 เป็นหนึ่งใน identifiers ใน Knowledge Graph — เมื่อเว็บของเราระบุ ICD-10 code ใน Schema (MedicalCondition.code) Google สามารถ match entity ของเราเข้ากับ entity ของเขาได้ทันที ไม่ต้องเดา

2. E-E-A-T Signal
การใช้ ICD-10 code แสดงว่า content ถูกเขียนโดยคนที่มีความรู้ทางการแพทย์ — ไม่ใช่ content ทั่วไปที่เขียนจาก Google search

3. Cross-reference กับ Medical Databases
PubMed, WHO, CDC ทั้งหมดใช้ ICD-10 — เมื่อเราอ้างอิง ICD-10 เดียวกัน content ของเรามี "สกุลเงินเดียวกัน" กับ authoritative sources

4. AI Search Precision
AI chatbots ใช้ ICD-10 ในการระบุโรค — เว็บที่ใส่ ICD-10 ถูกดึงข้อมูลได้แม่นยำกว่า เพราะ AI ไม่ต้องตีความจาก natural language

11.4 Wikidata IDs ทำทำไม

Wikidata คือ knowledge base ที่อยู่เบื้องหลัง Wikipedia — ทุก entity มี unique ID (เช่น Q194304 = Dental Implant) ที่ Google Knowledge Graph ใช้เป็น backbone

วิธีที่ Wikidata ทำงานกับ Google

🔗
Google Knowledge Graph สร้างจาก Wikidata เป็นหลัก

เมื่อเราใส่ sameAs: "https://www.wikidata.org/wiki/Q194304" ใน Schema ของหน้า Dental Implant — เรากำลังบอก Google ว่า:

"หน้านี้ของเราพูดถึง entity เดียวกัน กับ Wikidata Q194304 (Dental Implant)"

ผลที่ได้:
  • Entity Disambiguation: Google ไม่สับสนว่า "implant" ของเราหมายถึงอะไร (dental implant? medical implant? breast implant?)
  • Knowledge Panel Eligibility: เว็บที่ link กับ Wikidata มีโอกาสปรากฏใน Knowledge Panel มากขึ้น
  • Cross-language Linking: Wikidata entity มีชื่อในทุกภาษา — ช่วย Google เข้าใจ hreflang ของเราดีขึ้น
  • AI Training Data: Wikidata เป็น training data ของ LLMs ส่วนใหญ่ — เว็บที่ align กับ Wikidata จะถูก AI เข้าใจดีกว่า

1 Crawl Efficiency Schema ช่วยให้ Googlebot เข้าใจโครงสร้างหน้าทันที ไม่ต้อง parse HTML ทั้งหมด — ใช้ crawl budget น้อยลง index เร็วขึ้น

3 YMYL Trust Signal สำหรับ health content (YMYL = Your Money Your Life) Google ต้องการ trust signals พิเศษ — Schema ทาง medical (MedicalCondition, MedicalProcedure, Physician) เป็น machine-readable trust signal ที่ชัดเจนที่สุด
4 Rich Results Eligibility FAQPage, HowTo, Product, LocalBusiness = trigger rich results ที่กินพื้นที่ SERP มากขึ้น — CTR สูงขึ้น 20-50% เมื่อมี rich results
5 AI Overview / SGE Google AI Overview (เดิมชื่อ SGE) สร้าง answers จาก structured data + trusted sources — เว็บที่มี Schema ถูกดึงไปแสดงใน AI Overview มากกว่าเว็บที่ไม่มี
6 Topical Authority Score Entity graph ที่ครบถ้วน (200+ entities, 26 clusters) บอก Google ว่าเว็บครอบคลุม topic แบบ comprehensive — ไม่ใช่แค่มี content มาก แต่มี content ที่เชื่อมโยงกันเป็นระบบ
7 Future-proofing Google + Bing + AI chatbots ทั้งหมดกำลังเคลื่อนไปทาง structured data + entity understanding — เว็บที่ทำตอนนี้จะได้เปรียบทบต้นเมื่อ algorithms เปลี่ยน

11.6 ผลต่อ AI Search โดยเฉพาะ

นอกจาก Google แล้ว AI Search (ChatGPT, Gemini, Perplexity, Claude) กำลังเปลี่ยนวิธีที่คนค้นหาข้อมูลสุขภาพ

เว็บที่ไม่มี structured data

AI ต้อง "อ่าน" natural language text แล้วพยายามเข้าใจ — อาจตีความผิด หรือข้ามไปเลย เพราะไม่มั่นใจ

เว็บที่มี structured data + entity

AI ดึงข้อมูลจาก Schema ได้ตรง — ตอบ user ได้แม่นยำ — cite กลับมาที่เว็บ เป็น source — สร้าง traffic ใหม่ที่ Google Search ไม่ได้ให้

🤖
AI Search Citation = SEO ยุคใหม่

เมื่อ Perplexity หรือ ChatGPT ตอบคำถาม "รากเทียม All-on-X" — AI จะ:
  1. ค้นหาเว็บที่มี structured data เกี่ยวกับ All-on-X
  2. ดึงข้อมูลจาก MedicalProcedure Schema ที่บอก howPerformed, bodyLocation, indication
  3. ตรวจสอบ E-E-A-T: มี Dentist attribution? มี references? มี dateModified ล่าสุด?
  4. สร้างคำตอบ + cite กลับมาที่เว็บเรา เป็น source

ถ้าไม่มีเว็บไทยเจ้าไหนมี MedicalProcedure Schema สำหรับ All-on-X — SmileScape จะเป็น source เดียวที่ AI ดึงไปใช้

11.7 สรุป: Stack ของเทคนิคทั้งหมดทำงานร่วมกันอย่างไร

Schema Markup = บอก Google ว่า content คืออะไร (machine-readable)
Entity Graph = บอก Google ว่า content เชื่อมโยงกันอย่างไร (relationships)
ICD-10 Codes = บอก Google ว่า entity นี้ match กับ medical standard ไหน (identity)
Wikidata IDs = บอก Google ว่า entity นี้คือ entity เดียวกับ Knowledge Graph (disambiguation)
Academic References = บอก Google ว่า content นี้อ้างอิงจากแหล่งที่เชื่อถือได้ (trust)
E-E-A-T Signals = บอก Google ว่าใครเป็นคนเขียน ตรวจสอบเมื่อไหร่ (authority)

ทั้ง 6 layer ทำงานร่วมกัน = Google เข้าใจเว็บ 100%
